## PaleoAST 1.1.2

A scientific desktop application for palaeontological and ecological
statistics: ordination, group comparison, morphometrics, macroevolution,
time series and spatial analysis, with publication figures throughout.

### Install

Two formats, from the same build. Pick either.

**`PaleoAST-1.1.2-windows-x64.msi`** -- the normal choice. Double-click it,
choose the install folder, and PaleoAST appears in the Start Menu with a
shortcut. It installs to `C:\Program Files\PaleoAST`, can be repaired, and
removes itself cleanly on uninstall. A desktop icon is available but off by
default: choose *Advanced* and tick **Desktop shortcut**.

**`PaleoAST-1.1.2-windows-x64-portable.zip`** -- no installer. Unzip anywhere
and run PaleoAST.exe. The folder must stay together, because the exe loads its
libraries from the _internal subfolder beside it. Use this on a machine where
you cannot install software, or to keep several versions side by side.

Both ship the identical file tree. The MSI is not a separate build: it
packages the same `dist/PaleoAST` directory the zip was made from, so the
installer and the portable copy cannot drift apart.

Requires R (https://cran.r-project.org/) and ggplot2 for the R plotting
features. Everything else is self-contained.

**Upgrading from 1.1.1** -- run the 1.1.2 installer over the top. The two share
an Upgrade Code, so it replaces the old install in place rather than leaving a
second copy.

## The plot menu

This is the reason most people should move to 1.1.2.

Every figure PaleoAST drew before was attached to one analysis -- scores for
a PCA, indices for a diversity run. There was no way to take two columns out
of the sheet and plot them, which is the first thing you do in PAST.

*File > Plot* now covers PAST's menu item for item: XY with an optional fitted
line and log axes, XY with error bars, histogram, bar chart, box plot, pie
chart, stacked chart (with a normalise-to-percent mode), percentiles, normal
probability plot, ternary, bubble, matrix, mosaic, Venn for two and three
sets, radar, polar, vector field, network, and the 3-D family -- scatter,
line, bubble, surface and parametric surface.

The ternary and mosaic plots are the two worth naming: both take counts, not
percentages, because a count table is what a palaeontological data set
actually is.

## Every categorical figure now uses Okabe-Ito

**This changes how your figures look.** Previously the on-screen figures used
one palette and the exported ones used another, so a colour chosen in
Preferences changed the file and left the picture on screen untouched. Both
now read the same table, and the default is Okabe & Ito (2008) on both --
separable under deuteranopia, protanopia and tritanopia, and in greyscale.

Three settings are selectable in Preferences: Okabe-Ito, greyscale, and
ColorBrewer Dark2. Sequential ramps (bubble size, surface height) deliberately
do not come from a categorical palette: a magnitude wants neighbouring
colours to read alike, which is the opposite of what a class palette is for.

## Also in this release

- **k-medoids (PAM), DBSCAN and k-nearest-neighbours classification**, to go
  with the existing hierarchical and k-means clustering. PAM is fitted by
  greedy BUILD followed by a SWAP hill-climb, so its centres are always actual
  observations rather than means.
- **Abundance model fitting** is now in the analysis list: log-series,
  log-normal, geometric and broken-stick, ranked by AIC.

### Three fixes worth knowing about

Each of these was a control that looked like it did something and did not.
None was caught by a test, because in every case the dialog still ran and
still produced a result.

- The allometry dialog offered **"RMA (reduced major axis)"** next to OLS.
  Choosing RMA ran the OLS regression and labelled the output RMA. RMA needs
  measurement-error estimates to fit error in both axes, and the dialog does
  not collect them, so the option is gone until that is implemented; a method
  you cannot compute correctly is worse than one you cannot reach.
- The PCA dialog's **"Use correlation matrix"** checkbox was a mirror of the
  Similarity Matrix combo. Unticking it by hand did nothing. The combo is what
  reaches the engine and still states the choice.
- The macroevolution dialog offered **"Starting consensus from: Consensus /
  First specimen"**. The second mode does not exist in the engine.

A new test now finds this class of defect structurally, by looking for a widget
whose value is never queried.

### One correction to 1.1.1's release notes

1.1.1 said the palette dropdown offered Okabe-Ito, greyscale, Dark2 and
viridis. In that build the dropdown had no effect at all: the preference key was
collected by the dialog and then dropped by the code that saves preferences,
which did not mention it. Every export in 1.1.1 came out in the Okabe-Ito
default. The options do what their labels say from this release onward.

## Where this stands against PAST

`docs/parity/past4_features.json` in the source repository is a
feature-by-feature inventory of PAST 4, transcribed from its official reference
manual: 242 entries across twelve menus. It is there so that "reproduces
everything PAST has" is a state that can be checked rather than judged by eye.

The largest known gaps, all still open: radiocarbon calibration (needs the
IntCal curve data, which is not bundled), stratigraphic range confidence
intervals, the point-alignment and kernel-density tools, modern analog
technique, and UMAP/ISOMAP ordination.
