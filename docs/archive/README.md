# 归档的历史报告

这些是 PaleoAST 某一时刻的**审查与升级记录**。它们保留下来有两个理由：

1. **知道一个缺陷是怎么被发现的，比知道它被修好了更有用**——同一个坑会再踩一次。
2. 报告里的判断有时是错的（见下），留着它们才能看出**判断本身**是怎么演进的。

## 但不要把它们当成现状

**这些文件描述的是过去某个时刻的仓库，不是现在的。**
它们里面的行号、文件路径、缺陷数量、结论，**大多已经不成立了**。
比如 `REVIEW_REPORT_2026.md` 说统计核心里有若干缺陷——那些后来修掉了；
`UI_IMPROVEMENTS.md` 描述的界面改造，早被设计体系取代。

**当前的事实在这三处**：

| 想知道的 | 去哪 |
|---|---|
| 现在有哪些分析、每个被怎么验证过 | `docs/validation-matrix.md`（自动生成） |
| 每个方法的假设、适用条件、文献 | `docs/methods/` |
| 现在还没做的、为什么 | `FIX_PLAN_2026-10-19.md` |
| 改了什么 | `CHANGELOG.md` |

## 一条方法论上的提醒

**这些报告里的结论，本身也会过期。**
"已修复"这个状态只在写下的那一刻成立。仓库里现在的保证不来自这些文档，
而来自**可执行的检查**：覆盖率棘轮、验证覆盖矩阵、方法文档的防腐化断言、
以及与 R 的活跑交叉验证。
